# Staging Environment Setup

This project supports environment-specific Firebase configs via `EXPO_PUBLIC_APP_ENV`.

## 1) Create Firebase projects
- `simplyidle-dev` (development)
- `simplyidle-staging` (staging)
- `simplyidle-prod` (production)

## 2) Configure environment variables
Set `EXPO_PUBLIC_APP_ENV` in your environment or CI pipeline:
- `dev` for local development
- `staging` for pre-release validation
- `prod` for production

Then provide Firebase variables in `.env.local`:

```bash
EXPO_PUBLIC_APP_ENV=staging

# defaults (dev/fallback)
EXPO_PUBLIC_FIREBASE_API_KEY=...
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN=...
EXPO_PUBLIC_FIREBASE_PROJECT_ID=...
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET=...
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=...
EXPO_PUBLIC_FIREBASE_APP_ID=...
EXPO_PUBLIC_FIREBASE_MEASUREMENT_ID=...

# staging overrides
EXPO_PUBLIC_FIREBASE_API_KEY_STAGING=...
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN_STAGING=...
EXPO_PUBLIC_FIREBASE_PROJECT_ID_STAGING=...
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET_STAGING=...
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID_STAGING=...
EXPO_PUBLIC_FIREBASE_APP_ID_STAGING=...
EXPO_PUBLIC_FIREBASE_MEASUREMENT_ID_STAGING=...

# production overrides
EXPO_PUBLIC_FIREBASE_API_KEY_PROD=...
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN_PROD=...
EXPO_PUBLIC_FIREBASE_PROJECT_ID_PROD=...
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET_PROD=...
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID_PROD=...
EXPO_PUBLIC_FIREBASE_APP_ID_PROD=...
EXPO_PUBLIC_FIREBASE_MEASUREMENT_ID_PROD=...
```

## 3) CI recommendations
- PR builds: `EXPO_PUBLIC_APP_ENV=staging`
- main release builds: `EXPO_PUBLIC_APP_ENV=prod`

## 4) Runtime behavior
`src/services/firebase.ts` resolves variables in this order:
1. `EXPO_PUBLIC_FIREBASE_<KEY>_<APP_ENV>`
2. fallback `EXPO_PUBLIC_FIREBASE_<KEY>`

This allows gradual migration without breaking local dev.
